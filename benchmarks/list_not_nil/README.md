# LIST_NOT_NIL benchmark

This benchmark uses HOL4's `LIST_NOT_NIL` proof as a realistic list-theory
workload. The theorem states `!ls. ls <> [] <=> (ls = HD ls::TL ls)`, and its
source proof calls `metis_tac[list_CASES, HD, TL, NOT_NIL_CONS]`. The source was
recorded from HOL4 revision `61058e3f0d4c7ad6b4e5ea0211c2b635b1b22b80`,
`src/list/src/listScript.sml`.

## Two Measurements

The native-proof measurement times each prover's own way of proving the same
statement from corresponding library facts. `hol4.sml` runs the source
`METIS_TAC` proof, which constructs 3,413 HOL4 theorems on the recorded build;
`hol_light.ml` splits on `list_CASES` and rewrites with `HD`, `TL`, and
`NOT_CONS_NIL`. These times include tactic work and kernel calls, but exclude
library startup and proof validation. Hotaru has no equivalent tactic, so this
measurement has no Hotaru row.

The certificate-import measurement checks one fixed proof generated by HOL4's
OpenTheory recording kernel. The checked-in `list_not_nil.art` contains 88,221
lines, including 7,968 theorem-producing instructions and 31 references to
pre-existing library theorems. Each implementation reads, parses, and checks
the same article inside the timed interval; setup, warmup, and final theorem
validation are outside it. The certificate expands derived HOL4 rules and
omits discarded search branches, which is why its instruction count differs
from the 3,413 calls in the native proof.

The imported theorem is conditional on the article's external theorem inputs.
HOL4 and HOL Light match those inputs against their existing library theorems;
Hotaru loads the fixed input statements as theory axioms before timing. Each
importer rejects an article whose inputs or final theorem fail its checks.
The certificate adapter keeps the article's equality encoding private and
stores each proof as one opaque theorem. It calls only logical rules such as
`abs`, `mk_comb`, `symm`, `trans`, `eq_mp`, and `deduct_antisym`; the verified
kernel recognizes the canonical HOL equality encoding internally whenever one
of those rules needs to align representations. No FFI entry point exposes an
equality conversion operation. Fused paths use logical rules with established
semantics, such as `inst_ty_term`; assumption contraction is part of the
ordinary `eq_mp` and `deduct_antisym` rules. The import time includes this
kernel-side alignment and any remaining structural contraction.

This workload applies the benchmark's public-interface naming rule to every
fused path. Each exported call must state a recognizable logical operation and
its theorem-level inputs and output, while certificate parsing, equality
encoding alignment, and assumption storage remain internal. A name such as
`eqMpThenCompact` would describe adapter control flow, so it is excluded even
if the same sequence could be faster than composing the semantic rules.

## Run

The smoke profile checks the three importers with one import and one timed
trial. A standard run uses seven trials of 16 imports each. The runner
builds the Hotaru release example and HOL Light executable, then uses the
provided HOL4 heap.

```sh
python3 benchmarks/list_not_nil/run_replay.py --profile smoke \
  --hol-light-switch /path/to/opam/switch \
  --hol4-bin /path/to/HOL/bin/hol

python3 benchmarks/list_not_nil/run_replay.py --profile standard \
  --hol-light-switch /path/to/opam/switch \
  --hol4-bin /path/to/HOL/bin/hol
```

The native-proof runner compares the two systems that can perform the proof
from library lemmas. It uses seven trials of 256 proofs in the standard
profile. Specify `--systems hol4` or `--systems hol-light` to run one system.

```sh
python3 benchmarks/list_not_nil/run_native.py --profile standard \
  --hol-light-switch /path/to/opam/switch \
  --hol4-bin /path/to/HOL/bin/hol
```

The runners write raw trials, source hashes, implementation metadata, and
median/range summaries under `target/benchmarks/list_not_nil/`. Run systems on
an otherwise idle machine, and repeat comparative runs in different system
orders to reduce thermal and cache-order effects. The suite is deliberately
outside CI because its measurements depend on external HOL installations.
The [measured results](RESULTS.md) include both system orders, historical
adapter variants, the current public-rule adapter, and their raw trial files.

## Provenance

The article was exported by `export_hol4.sml` after reproving the theorem in
an isolated HOL4 `--otknl` build at the source revision above. Its SHA-256 is
`0b187bac4d8d3d41fcd1f485efc63fcd018e30c56311be029e4f36cef42431bd`.
The recording uses the OpenTheory v6 command format plus `sym` and `trans`
commands emitted by HOL4's exporter. The runner generates a temporary HOL4
reader with those two kernel rules; it leaves the installed reader intact.
`inspect_article.py` provides a structural inventory of commands, external
theorems, and partial applications of logical constants; it does not check
proof validity. The three importers perform that check independently.
